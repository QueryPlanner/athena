---
title: Usage and cost
description: What each turn records, and why model calls are not messages.
---

Every turn writes one row to `runs` alongside the transcript: token usage by
kind (input, output, cached input, reasoning), the number of completion
requests Rig issued, per-call finish reasons, and the provider's raw
response.

```bash
cargo run -- usage
```

```text
session   runs  calls  in   out  cached
live      1     2      256  26   0
```

## Model calls are not messages

`add 21 and 21` is one turn, two completion requests and four transcript
rows:

```text
call 0  finish_reason=tool_calls  in=111  out=21   <- model asks for add()
call 1  finish_reason=stop        in=145  out=5    <- model answers "42"
```

Input grows between the two because the tool result re-enters context. That
cost is invisible in `messages`, and it is the reason `runs` exists.

## Raw responses

`runs.calls_json` keeps each call's raw provider response as opaque Rig
JSON. For OpenRouter it carries detail Rig does not model, such as upstream
routing and cost. It is also an unredacted copy of the response and
dominates row size (1737 bytes versus 263 in the run above). Set
`RUNS_STORE_RAW=0` to drop it.

Telemetry is written after the transcript, and a failure to write it is a
warning, not an error: losing a cost row must never cost you a reply.
