## Security

<Callout type="error">
  **The HTTP API is unauthenticated. Do not expose it publicly.**
</Callout>

- Whoever can reach the port can act as any user by setting
  `X-Athena-User`, read every session, spend the OpenRouter credit, and use
  the agent's tools in any session's sandbox. Loopback is the default and refuses foreign `Host`
  headers, but every local process is still trusted. Put an authenticating
  proxy in front before listening anywhere else.
- Every distinct `X-Athena-User` value creates a `users` row, even for a
  read. There is no rate limit or cap beyond the 256-byte header limit.
- The Telegram bot is open to anyone. There is no allowlist and no per-user
  budget; `/usage` and the `runs` table show who spent what.
- Provider errors are logged to stderr in full and can include account
  details from the provider's error body. Message text is never logged.
- Sign-in links (`browser_login_link`) are protected only by their token:
  anyone who can reach the server with the link drives the user's signed-in
  browser for an hour. Saved sign-ins are stored unencrypted and loaded into
  every sandbox of their user, where the agent's tools can read them.

- A stdio MCP server in `ATHENA_MCP_CONFIG` runs on the host with athena's
  permissions, outside the sandbox, and one connection serves every user.
  Whoever can write that file, or the environment it reads, chooses what
  runs. See [MCP servers](/docs/mcp).

- Google Health: if the Google OAuth consent screen is in "Testing"
  status, Google expires refresh tokens after 7 days, and each user has to
  `/connect_health` again every week. Publish the consent screen to avoid it.
  The URL a user pastes to connect holds a one-time code and stays in their
  Telegram chat history until they delete it; the bot never passes it to the
  model or saves it, and the code is useless without the client secret. What
  `health_summary` returns is sent to the model provider and saved in the
  session. A bare code pasted without its URL is not recognised.

- Daily brief: it is a scheduled agent turn like a reminder task. The agent
  has no cap on model calls per turn, and a scheduled turn still has the
  agent's write tools (it cannot confirm anything, because it has no user
  message). The fixed prompt tells the model to call three read tools and to
  treat their results as data, but that is an instruction, not a filter. A
  brief lost to a crash or a failed send is not sent again that day. Changing
  time zone can shift a brief by up to a day.

## Durability

- A crash mid-turn loses that turn, and so does a second Ctrl-C while
  `serve` drains. Persistence is one append per turn, not per model call.
- Dropping `send`'s future after the append but before the run row leaves
  transcript rows no run covers. `send_detached` and `send_stream` do not
  have this problem.
- A turn that panics records no run. A streamed client gets an `internal`
  error event.
- Telegram delivery is at most once. A crash or `kill -9` loses queued
  messages, and a reply whose send fails is lost though its transcript is
  saved.
- Deltas already streamed cannot be taken back if the transcript then fails
  to save.

## Behaviour

- Compaction is a summary, so it is lossy, and it waits until the context is
  at 80% of the model's window: with the default model that is 840 000 tokens
  re-sent on every call until it happens. It cuts only between messages, so
  one prompt or tool result that alone fills the window cannot be helped. A
  session already over its window when compaction is switched on may not be
  rescued, and a summary model with a smaller window than the agent's fails
  on a big session (the turn goes on without compacting). The window is
  OpenRouter's largest for the model, not the provider's. There is no
  `/compact` command and no token cap below the percentage yet. See
  [Compaction](/docs/compaction).
- Turns on one session are serialized within a process. Across processes the
  second to finish is refused with `Conflict`; that includes a scheduled task
  in the bot racing an HTTP turn on the same session.
- Reminders: a `notify` is sent at least once (a crash right after Telegram
  accepts it sends it again); an `agent_task` runs at most once (a crash
  mid-turn loses that run). A scheduled task's reply follows the same rules
  as any turn's. A scheduled task only runs once the user has replied with
  its id and confirmation code, so a page or file cannot schedule one by
  itself; but a user who confirms a task without reading the preview gives
  it the same authority as their own message, every time it runs.
- A user's own skills (`skill_install`, `skill_create`) are added in two
  steps, a preview and then `skill_confirm(preview_id)`, but nothing checks
  that the user agreed in the chat. The agent is told to show the preview and
  ask first; Athena relies on the model doing so. A web page, file or skill
  that talks the model into confirming could therefore install a skill. The
  preview expires after 10 minutes, works once and is tied to the user and
  session; GitHub text is labelled untrusted when read, and skills are only
  read, never run. A user's skill can still steer the model afterwards.
- Axum answers some malformed requests itself, outside the JSON error
  shape: unknown paths (`404`), wrong methods (`405`), bodies over 2 MB
  (`413`).
- Telegram has no headings, lists or tables, so Markdown is approximated: a
  heading is bold text, a list is `•` or numbered lines, a table is
  monospace (wider than 60 columns, a `Header: value` block per row). Code,
  links and blockquotes cannot contain other formatting in Telegram, so
  bold code is code only, and code or a table inside a quote loses its
  monospace styling. A link inside a quote or a table cell, or one that is
  not http, https or mailto, is shown as `text (address)` and is not
  tappable. Raw HTML is shown as written.
- Edited Telegram messages are ignored; photos and other non-text messages
  get "I only read text messages."
- The selected session is Telegram state. The CLI uses `default` unless
  given a name, and `sessions` does not mark the selection.
- No timing beyond whole-turn wall clock.

The full list, with details, is in the
[README](https://github.com/QueryPlanner/athena#known-limits).
