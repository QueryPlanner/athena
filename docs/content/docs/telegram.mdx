---
title: Telegram
description: Run athena as a Telegram bot with per-user sessions.
---

```bash
export TELEGRAM_BOT_TOKEN=123456:ABC...   # from @BotFather
ATHENA_DB=$PWD/agent.db cargo run -- telegram  # long polling; Ctrl-C stops
```

`athena telegram` needs `OPENROUTER_API_KEY` and `TELEGRAM_BOT_TOKEN` and
checks both before it opens the database.

<Callout type="warn">
  The bot is open to anyone who finds it, and every turn spends the owner's
  OpenRouter credit. See [Known limits](/docs/known-limits).
</Callout>

It answers private chats only. A group message is ignored and logged: in a
group every member would read one member's conversation.

## Users and sessions

Each Telegram user is the user `telegram:<their Telegram user id>`, so
`cargo run -- --user telegram:ID sessions` shows what the bot stored for
them. They talk in one session at a time: `default` until they pick
another. The pick is stored (the `selected_sessions` table), so it survives
a restart.

## Commands

| Command | What it does |
|---|---|
| `/new NAME` | Create session NAME and switch to it. Without NAME, picks `chat-N`. |
| `/sessions` | List your sessions with message counts; `*` marks the current one. |
| `/switch NAME` | Switch to an existing session (`default` always exists). |
| `/usage` | Turns, model calls and tokens per session. |
| `/connect_health` | Connect Google Health (read-only): send the link it gives you, then paste back the address Google sends your browser to. See Google Health. |
| `/disconnect_health` | Revoke Google Health access and delete the stored token; synced daily numbers stay. |
| `/help`, `/start` | What the bot is, the current session, the commands. |

The commands are registered with Telegram's command menu at startup. Any
other text is a prompt for the current session.

## Daily training brief

Ask in plain words ("send me a training brief every morning at 6:30") and the
agent turns it on with `daily_brief_set`; `daily_brief_status` and
`daily_brief_off` read and stop it. Each morning at that time on your clock
(`timezone_set`, daylight saving followed) the bot runs one turn in your
current session and sends you a short brief: what is due today (Push, Pull,
Legs, VO2), last session's numbers with what to aim for, your last three days
of sleep, resting heart rate and steps from Google Health (left out if it is
not connected), and yesterday's calories. It waits up to 30 minutes for that
morning's Google Health sync. The prompt is fixed in the program, so it needs
no confirmation code as a reminder task does.

It is at most one a day. If you are mid-turn it waits and tries again every
30 seconds; more than 4 hours late, that day's brief is skipped, not made up.
If Telegram refuses the message (you blocked the bot), the brief is switched
off. Like reminders, only `athena telegram` sends it.

## Reminders

Ask in plain words ("remind me at 6 to call mum", "every weekday at 7:30
summarise the news for me") and the agent schedules it with its reminder tools.
A `notify` reminder sends you its text; an `agent_task` runs its text as a
task in your current session and sends you the reply. A task is only
scheduled once you confirm it: the agent shows it with a code, and you reply
`confirm #<id> <code>` within 10 minutes. They repeat once, daily
or weekly on given days, at a time on your clock, and follow your time zone
(`timezone_set`) and daylight saving.

The bot process checks for due reminders every 30 seconds; the HTTP server
never sends them, so a staging environment runs them only if it has its own
`TELEGRAM_BOT_TOKEN`. A run that comes late (the bot was down) is sent once
and says so; missed repeats are not made up. A task that falls due while you
are mid-turn waits for you for up to 30 minutes, then is skipped with a note.
If you block the bot, your reminders stop. Limits: 50 active reminders, 10 of
them tasks, 20 task runs a day.

## Behaviour

- While the model works the bot shows "typing...".
- The model's Markdown is rendered for Telegram: bold, italic,
  strikethrough, `code`, fenced code with its language, links, blockquotes,
  headings (bold), bullet and numbered lists, and tables (an aligned grid in
  a code block). The bot sends plain text plus formatting entities, never a
  parse mode, so a stray `*` or `_` stays as written and cannot make Telegram
  refuse a message. If Telegram answers "Bad Request" to a formatted
  message, that message is sent again as plain text.
- A reply over Telegram's 4096-character limit is split at a blank line near
  the limit if there is one, else a line break, else a space, never inside a
  character. A code block or style that crosses the cut is closed and
  reopened in the next message. At most 8 messages, then a note that the
  rest is in the transcript.
- A 429 from Telegram is retried after the delay it asks for.
- Each turn runs in its own task, so a slow model never holds up another
  user. One user gets one turn at a time: a message that arrives while their
  turn runs is answered "Still working on your last message..." and dropped.
  Commands still answer at once.
- Errors are logged to stderr and answered with one short line; the bot
  keeps running.
